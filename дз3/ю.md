Створити два Python-скрипти: task_server.py і task_client.py, які працюють по TCP
(AF_INET, SOCK_STREAM) на localhost і заданому в коді порту.
Обмін даними між клієнтом і сервером має бути текстовим. Кожне повідомлення —
окремий рядок, що закінчується символом \n. Сервер і клієнт повинні коректно
працювати з TCP-потоком.
Сервер має підтримувати одночасну роботу кількох клієнтів. Для кожного нового
клієнта створюється окремий потік. Клієнтська програма також має використовувати
два потоки: один для введення команд і надсилання їх на сервер, інший — для
постійного читання відповідей сервера.
Сервер повинен реалізовувати спільний список завдань. Для кожного завдання
потрібно зберігати: унікальний номер, автора, текст завдання та статус (OPEN або
DONE).
Після підключення кожен користувач отримує тимчасове ім’я за замовчуванням.
Команда /nick <name> змінює ім’я користувача. Імена користувачів мають бути
унікальними.
Команда /who повертає список підключених користувачів.
Команда /add <text> додає нове завдання до спільного списку. Сервер повинен
повертати номер створеного завдання.
Команда /list повертає список усіх завдань із номером, автором, текстом і статусом.
Команда /done <id> позначає завдання як виконане.
Команда /delete <id> видаляє завдання зі списку.
Команда /my повертає лише ті завдання, автором яких є поточний користувач.
Команда /msg <name> <text> надсилає приватне повідомлення конкретному
користувачу.
Команда /quit завершує сесію клієнта: сервер надсилає повідомлення про завершення
і закриває з’єднання.
Будь-який рядок, який не починається з символу /, сервер має трактувати як звичайне
повідомлення і розсилати всім підключеним клієнтам.
Архітектурно сервер має бути побудований так, щоб потоки клієнтів передавали події у
спільну чергу queue.Queue, а окремий потік-обробник забирав події з черги та
виконував розсилку повідомлень і службові дії.
Сервер не повинен аварійно завершуватись через неправильні команди. Для
невідомих команд або неправильних аргументів сервер має повертати повідомлення
про помилку.
